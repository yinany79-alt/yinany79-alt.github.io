## 让问题从提出走到解决

训练或环境出了问题，用户需要翻文档、查页面、到群里提问，再提交工单。信息在不同入口间流转，诊断结论也难以复用。

围绕缩短问题到解决的路径，我推进算法中台答疑 Bot 建设，把文档解释、实时查询、任务诊断和执行型操作接入统一问答流程。

## 三轮架构迭代，明确每个判断的依据

基于 JoyAgent、LangGraph、HERMES 推进三轮架构迭代，建设文档问答、任务诊断、工单诊断和兜底服务的多路由 Agent Harness。

统一意图识别、事实取证、能力调用与结果校验链路，明确 SOUL、Skill、Plugin、知识库的协同方式。通过提示词编排、脚本/API 约束与实时工具确认，让复杂问题的执行过程可以检查、回溯和改进。

## 独立从零搭建一个评测系统

我完成了数据库设计与建设、前后端开发、部署和上线。系统连接评测集管理、批量任务执行、结果存储、版本对比与报告展示，支持两类互补的评测：

- **端到端任务评测**：从用户问题出发执行完整链路，检查任务是否完成、回答是否正确、结论是否有证据。
- **轨迹多维评分**：结合 LLM-as-Judge、Rubric 与规则校验，检查工具选择、参数、事实一致性和失败恢复；用人工复核校准评分。

这些方法让一次失败能被定位到具体决策，并转化为回归 Case。Bot 当前日均请求 800+，Beta 与正式版本双线迭代，每周交付 2–3 个版本。

## MiniCPM5-2B：从评测问题走向垂域训推

围绕平台知识与 Agent 行为内化，完成私域样本审计、全参 SFT、多组超参数及 Checkpoint 对照。起始实验审计 14,048 条训练样本和 345 条评测样本，在 Magnus 上完成 25.17 亿参数模型的训练验证。

随后打通 BF16 权重导出、模型发布和 H200/vLLM 部署，接入 MiniCPM XML Tool Parser，验收问答、流式/非流式工具调用及工具结果回传，并将失败 Case 回流数据修订和重训。

最终测试报告通过验收：在本次垂域问答测试范围内，与 DeepSeek V4.1 Flash 基本持平。这个结论限定于该测试范围；下一阶段计划推进 RL，优化任务决策与工具使用。

## 用评测推动每一次发布

线上反馈与评测发现进入同一条 Case Review 流程。候选版本与生产基线对比，完成 Bad Case 回归后进入灰度与正式发布，再由运行监控提供下一轮改进依据。
