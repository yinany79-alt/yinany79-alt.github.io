## 从反复切换环境，到围绕任务工作

算法用户在本地 IDE 写代码、在 Notebook 调试，再到平台提交训练。每次切换，都要重新配置环境、查资源、找指标。我的工作是把这些动作连成一条可执行、可观察的研发链路。

9N-Harness 是这条链路的桌面入口：读取用户选择的项目代码、配置与文档，按任务选择 Skill、工具或 Workflow，在平台账号、项目权限和资源边界内持续推进任务。

## 把平台能力组织成可执行的产品

推动 OpenAPI、SDK、CLI 与 30+ 原子能力建设，将训练、资源、日志、模型和指标组织为统一能力底座。平台页面、自然语言调用、编程集成各有入口，共用同一组可检查的执行能力。

工作台预置 18 个 Skills 和 6 条算法 Workflow，涵盖训练脚本评审、实验自动调优、CTR 特征消融、召回与相关性调优。一次实验可以沿着下面的过程推进：

> 检查项目 → 设计实验 → 提交训练 → 等待完成 → 判断指标 → 记录结果

需要把关的地方保留人工确认；京东 SSO、项目权限和资源边界随任务沿用，执行过程可追踪。

## Skill 要能被使用，也要能被改进

参考 Anthropic Skill Creator 规范，统一触发条件、`SKILL.md` 与 scripts/references 分层，建设 `9n-train`、`9n-ssh-connect`、`9n-debug` 等核心 Skill。把数据、资源、显存与依赖检查放到提交之前，让高成本错误更早暴露。

通过 Hook 记录调用过程，把成功实验、失败 Case 和用户反馈带回回归验证。阶段统计中，官方 Skills 近 7 日调用 4,522 次，周活用户 450 人。

## 开发体验，要落到少几次手工操作

针对 Notebook 无外网等环境约束，完成 Jupyter AI、Claude Code 与 Claude Code Router 的调研、原型验证及产品集成。Claude Code 实例覆盖率从 0% 提升至 75.2%。

建设一键 SSH 脚本和连接 Skill，连接本地 IDE 与云端调试环境，远程连接耗时从约 30 分钟降至 3 分钟以内。
