# 杨弋南个人技术站信息密度改版设计

日期：2026-09-16  
状态：待用户最终审阅  
适用站点：杨弋南个人技术站

## 1. 背景与目标

当前站点已经具备个人介绍、交互拓扑、项目、文章、简历和关于页面，但首屏留白过多、信息密度偏低，导航和栏目名称以英文为主，文章页使用过大的标题，整体更像一次性的视觉展示页，而不是可以长期维护和日常阅读的个人技术空间。

本次改版的目标是把网站调整为“技术工作台 + 个人日志流”：

- 默认以中文呈现，不提供中英文切换。
- 首屏同时回答“我是谁、我在做什么、我关注什么、如何查看简历”。
- 保留现有 Agent 拓扑作为网站的技术辨识度，但降低其面积占比。
- 提高首页和文章页的信息密度，减少无意义留白与巨型标题。
- 建立适合长期维护的项目、文章和个人状态数据结构。
- 在浅色和星球模式下都保持清晰、克制、有层次的视觉体验。

## 2. 目标读者与核心任务

主要读者包括招聘方、AI Infra 与算法工程同行，以及通过文章进入网站的技术读者。

不同读者进入网站后应能快速完成以下任务：

1. 在首屏理解杨弋南的角色定位与重点方向。
2. 查看当前工作、代表项目与可验证实践。
3. 阅读结构清晰的技术文章。
4. 下载或查看简历。
5. 了解求职状态：目前关注 AI Infra、Agent Harness、大模型训练平台及模型数据策略相关机会。

## 3. 信息架构

### 3.1 全站导航

顶部导航统一使用中文：

- 首页
- 项目
- 文章
- 简历
- 关于我

右侧保留浅色与星球模式切换。默认首次访问使用浅色；用户手动选择后在当前浏览器持久化。导航采用轻量毛玻璃悬浮层，在滚动后保持可访问，但不遮挡正文。

### 3.2 首页结构

首页从上到下分为五个连续区域。

#### A. 技术工作台首屏

桌面端采用左右布局，移动端改为单列：

- 左侧为个人信息中心。
- 右侧为缩小后的交互技术拓扑。
- 下一屏内容在首屏底部露出一部分，减少“满屏留白”的割裂感。

个人信息中心按以下顺序呈现：

1. 欢迎语：“欢迎来到我的空间”。
2. 姓名：“杨弋南”。
3. 角色定位：“AI Infra 产品 / Agent Harness / 大模型训练平台”。
4. 一句个人表达，说明关注如何让复杂训练与智能体系统可运行、可评测、可迭代。
5. 当前工作方向标签。
6. 求职状态：“关注相关机会”。
7. 两个主要操作：“查看简历”和“了解我的工作”。

姓名不再使用当前等宽大字。改用中文衬线字体栈，桌面端约 52–60px，移动端约 38–44px；通过字体、位置和留白成为视觉中心，而不是依靠夸张字号。

#### B. 目前在做

用紧凑的信息模块展示四个方向：

- Agent Harness 建设
- Skill 体系与 Loop Engineering
- 大模型训练与实验治理
- 生成式推荐与算法基础设施

每项包含一行背景、一行当前动作或产品职责，以及一个可进入项目详情的链接。模块避免虚构进度或指标，只复用现有已确认内容。

#### C. 重点项目

展示三项代表项目，每项包含项目名称、领域标签、简短问题定义、个人职责和关键结果。桌面端可使用三列或紧凑横向列表，移动端为单列。卡片不能只展示抽象口号，必须能让招聘方快速理解项目的背景、行动和收益。

#### D. 最近文章

首页直接展示最近 4–6 篇文章，按日期倒序排列。每条包含日期、标题、简短摘要和标签，点击进入文章详情。首页只做最新内容入口，不复制完整文章页。

#### E. 经历与联系

展示北京大学信息管理系教育经历、简历查看与下载入口、GitHub，以及后续由用户确认的公开联系方式。没有确认的联系方式不渲染占位内容。

### 3.3 文章页结构

文章列表页改为日常博客式时间流，不使用占据大面积的巨型标题。

页面顶部只保留：

- 较小的“文章”标题。
- 一句栏目说明。
- 标签筛选区域。

文章按发布日期倒序排列。每条文章显示：

- 发布日期
- 标题
- 1–2 行摘要
- 标签
- 预计阅读时间

标签可以点击筛选，筛选在浏览器本地完成，不新增服务端状态。无匹配结果时显示清晰的空状态和“查看全部”操作。文章详情继续使用现有 MDX 渲染，但同步缩小头部标题、提高正文可读宽度和元信息密度。

## 4. 视觉系统

### 4.1 色彩

默认浅色模式使用偏冷的纸白或浅灰蓝背景、炭黑正文和电光蓝主强调色。增加少量青绿色或暖橙色作为状态色，用于区分进行中、文章和机会状态；状态色必须服务信息层级，不把页面做成彩色仪表盘。

星球模式保留深色技术氛围，并继承相同的信息层级、强调色和交互状态。深色模式不能只是颜色反转，需要保证正文、标签、边框和拓扑连线有足够对比度。

### 4.2 字体

- 姓名：中文衬线字体栈，优先系统宋体风格。
- 标题与正文：清晰的中文无衬线字体栈。
- 日期、标签与技术元数据：等宽字体。

姓名负责建立个人气质，正文负责长时间阅读。正文默认不小于 16px，常用标签和操作不小于 14px，只有次要元数据可使用 12–13px。

### 4.3 表面与层级

毛玻璃只用于：

- 顶部悬浮导航
- 首屏个人状态与求职状态小卡片
- 拓扑节点详情面板

其余内容区域使用实色或低透明度浅色表面，避免整页玻璃卡片。卡片采用克制圆角、细边框和轻阴影；背景可使用低对比度网格、光晕或渐变，不能影响文字阅读。

## 5. 拓扑交互

拓扑图保留现有 Harness、Training、Recommendation 三种模式和节点详情能力，但从首屏主角改为右侧“技术关注图谱”。

改版要求：

- 减小画布占比并提高节点标签可读性。
- 当前模式与激活节点的反馈更明确。
- 点击节点继续打开对应实践详情。
- 拓扑数据与项目内容使用同一来源，避免两套描述漂移。
- 移动端允许横向压缩或简化连线，但不能遮挡标签和操作。

## 6. 动效与过场

动效用于建立节奏和反馈，不作为阅读门槛：

- 首屏进入时，欢迎语、姓名、状态信息依次轻微上移淡入。
- 拓扑节点低速呼吸，连线保持轻微流动。
- 内容区进入视口时使用 8–16px 位移与透明度过渡。
- 博客列表悬停时，标题轻微移动、标签和边框状态增强。
- 页面切换使用短促淡化，不做全屏遮罩或长时间转场。
- 所有非必要动效遵守 `prefers-reduced-motion`。

不引入重量级 3D 框架。优先使用 CSS transition、现有 Canvas 和少量浏览器原生能力。

## 7. 内容模型与组件边界

网站继续使用现有 MDX 与结构化配置，不引入 CMS。

### 7.1 内容模型

- 个人资料、当前工作和求职状态由统一站点配置维护。
- 项目使用现有项目 MDX 与结构化摘要。
- 文章 MDX 标准元数据包括：发布日期、标题、摘要、标签和预计阅读时间。
- 首页最近文章和文章列表从同一文章索引生成，避免手动重复维护。

### 7.2 组件边界

改版拆分为以下清晰模块：

- 中文悬浮导航
- 个人介绍与状态区
- 紧凑技术拓扑
- 当前工作区
- 重点项目区
- 最近文章区
- 文章时间流
- 标签筛选
- 主题切换
- 页面与区块过渡

每个模块读取明确的数据输入，避免把所有首页内容和交互继续堆在一个组件中。

## 8. 响应式与可访问性

- 桌面端首屏为左右结构；平板和手机改为个人信息在前、拓扑在后。
- 中文导航在窄屏使用紧凑菜单，不直接隐藏关键入口。
- 所有按钮、标签筛选和拓扑节点支持键盘操作与可见焦点。
- 主题开关提供明确的可访问名称。
- 页面在 200% 文本放大时仍能阅读和操作。
- 避免意外横向滚动，移动端不允许拓扑标签溢出视口。

## 9. 状态与错误处理

- 文章标签无匹配结果时显示空状态，并允许一键清除筛选。
- MDX 缺少非关键元数据时使用稳定回退；缺少标题或日期等关键字段时在构建阶段报错。
- 浏览器存储不可用时，主题切换仍在当前页面生效，但不承诺持久化。
- Canvas 不可用或用户减少动态效果时，拓扑保持静态可读状态。

## 10. 明确不做

本次不包含：

- 英文版本或语言切换按钮
- 搜索、评论、订阅、登录和后台管理
- 新的后端服务或数据库
- 重量级 3D 动画框架
- 虚构文章、工作数据、项目指标或联系方式

## 11. 验收标准

改版完成后必须验证：

1. 首页首屏在常见桌面和移动端尺寸下信息密度明显提高，姓名、欢迎语、当前工作、简历入口和机会状态无需滚动即可理解。
2. 全站导航使用中文且所有入口有效。
3. 浅色和星球模式覆盖首页、项目、文章、简历和关于页，并能记住用户选择。
4. 拓扑图模式切换、节点点击和详情面板正常。
5. 文章列表按日期倒序显示日期、标题、摘要、标签和阅读时间，标签筛选与空状态正常。
6. 页面与区块动效流畅，减少动态效果模式下自动降级。
7. 简历查看与下载正常。
8. 内容校验、ESLint、生产构建和关键产物检查通过。
9. 公网部署后检查首页、文章页、项目页和浏览器控制台，不出现阻塞错误。
